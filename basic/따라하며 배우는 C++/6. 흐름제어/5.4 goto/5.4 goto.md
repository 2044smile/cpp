# 5.4 goto

> 무조건 점프. 반복을 만들 수는 있지만, 반복문이 아니다.

---

## 설명

### goto가 하는 일

```cpp
double x;

tryAgain:                       // label (레이블)
cout << "Enter a non-negative number" << endl;
cin >> x;

if (x < 0.0)
    goto tryAgain;              // label 위치로 무조건 점프

cout << sqrt(x) << endl;
```

`goto`는 **조건 없이 지정한 레이블로 실행 위치를 옮깁니다.** 위 코드는 결과적으로 "음수를 입력하면 다시 물어보는 반복"이 되지만, 이건 `goto`가 반복 기능을 가져서가 아니라 **뒤로 점프했기 때문에 우연히 반복처럼 보이는 것**입니다.

여기서 중요한 구분이 하나 있습니다.

- `for`, `while` → **반복을 표현하는 문법**. 조건·증감·종료가 문법 안에 들어있다.
- `goto` → **점프를 표현하는 문법**. 반복은 부수 효과다.

### goto의 제약

`goto`는 **같은 함수 안에서만** 점프할 수 있습니다. 다른 함수의 레이블로는 갈 수 없습니다.

또 하나, **변수의 초기화를 건너뛰며 점프할 수 없습니다.** switch-case에서 봤던 문제와 같은 이유입니다.

```cpp
goto skip;
int x = 5;      // 이 초기화를 건너뛰게 됨
skip:
cout << x;      // 컴파일 에러: jump bypasses variable initialization
```

switch는 이걸 "런타임 미정의 동작"으로 넘겨버리는 경우가 있었지만, `goto`는 **컴파일 에러로 막아줍니다.**

## for / while / goto 비교

### 1. 반복 조건이 어디에 있는가

```cpp
// while — 조건이 앞에, 한 곳에 모여 있음
while (x < 0.0)
{
    cout << "Enter a non-negative number" << endl;
    cin >> x;
}

// for — 초기화 / 조건 / 증감이 한 줄에 모여 있음
for (int i = 0; i < 10; ++i)
{
    cout << i << endl;
}

// goto — 조건이 아래에, 점프 대상은 위에 흩어져 있음
tryAgain:
cout << "Enter a non-negative number" << endl;
cin >> x;
if (x < 0.0)
    goto tryAgain;
```

`for`와 `while`은 **"어디서 끝나는지"를 한눈에 알 수 있습니다.** 반복 범위가 `{}`로 명확히 닫혀 있죠.

`goto`는 그렇지 않습니다. 레이블은 함수 어디에나 있을 수 있고, 그 레이블로 점프하는 `goto`도 여러 개일 수 있습니다. **코드를 읽는 사람이 "이 레이블로 누가 오는가"를 직접 찾아다녀야 합니다.** 이것이 goto가 기피되는 가장 큰 이유입니다.

### 2. for vs while — 무엇이 다른가

기능적으로는 **완전히 동일합니다.** 서로 변환 가능합니다.

```cpp
for (int i = 0; i < 10; ++i) { /* ... */ }

// 위와 정확히 같은 동작
int i = 0;
while (i < 10)
{
    /* ... */
    ++i;
}
```

차이는 **의도의 표현**에 있습니다.

- `for` → **반복 횟수를 알 때.** 카운터 변수의 생명주기가 반복문 안으로 한정됩니다. `for(int i...)`의 `i`는 반복문 밖에서 접근 불가.
- `while` → **언제 끝날지 모를 때.** 사용자 입력, 파일 끝, 네트워크 응답 같은 상황.

`goto` 예제(`5.4 goto.cpp`)는 "사용자가 올바른 값을 넣을 때까지"이므로 **횟수를 모릅니다.** 따라서 `while`(또는 `do-while`)이 자연스러운 선택입니다.

### 3. 같은 코드, 세 가지 방식

```cpp
// goto 버전 — 원본
double x;
tryAgain:
cout << "Enter a non-negative number" << endl;
cin >> x;
if (x < 0.0) goto tryAgain;
cout << sqrt(x) << endl;

// do-while 버전 — 가장 자연스러움 (최소 한 번은 입력받아야 하므로)
double x;
do
{
    cout << "Enter a non-negative number" << endl;
    cin >> x;
} while (x < 0.0);
cout << sqrt(x) << endl;

// while 버전 — 초기값을 음수로 두는 트릭이 필요
double x = -1.0;
while (x < 0.0)
{
    cout << "Enter a non-negative number" << endl;
    cin >> x;
}
cout << sqrt(x) << endl;
```

`do-while`이 가장 깔끔합니다. **"일단 한 번 실행하고, 조건을 검사한다"** 는 구조가 원본 goto 코드의 흐름과 정확히 일치하기 때문입니다. `while` 버전은 `x = -1.0`이라는 **의미 없는 초기값**이 필요해서 조금 어색합니다.

## 비교표

| 항목 | `for` | `while` | `goto` |
|------|-------|---------|--------|
| 분류 | 반복문 | 반복문 | 무조건 점프 |
| 반복 범위 | `{}`로 명확 | `{}`로 명확 | 불명확 (레이블 위치에 따름) |
| 언제 쓰나 | 반복 횟수를 알 때 | 종료 시점을 모를 때 | 거의 쓰지 않음 |
| 점프 방향 | 앞으로만 (블록 끝→시작) | 앞으로만 | 위/아래 자유 |
| 카운터 변수 스코프 | 반복문 내부로 한정 | 바깥에 선언해야 함 | 해당 없음 |
| `break` / `continue` | 사용 가능 | 사용 가능 | 해당 없음 |
| 초기화 건너뛰기 | 불가능 (구조상) | 불가능 (구조상) | 컴파일 에러로 차단 |
| 가독성 | 좋음 | 좋음 | 나쁨 |

## 추가 학습 내용

### goto를 쓰지 말라는 이유 — "Go To Statement Considered Harmful"

1968년 다익스트라(Edsger Dijkstra)가 쓴 유명한 논문 제목입니다. 요지는 이렇습니다.

**goto가 많은 코드는 "지금 프로그램이 어느 상태인가"를 추적할 수 없게 만듭니다.** 반복문은 "이 블록 안에 있다"는 것만으로 상태가 설명되지만, goto는 어디서 왔는지 알 수 없습니다. 이런 코드를 흔히 **스파게티 코드(spaghetti code)** 라고 부릅니다.

실무 기준: **`goto`를 쓰고 싶다면, 거의 항상 `for`/`while`/`break`/`continue`/함수 분리로 더 낫게 표현할 수 있습니다.**

### 그래도 goto가 남아있는 이유

C 언어에는 예외 처리(`try-catch`)가 없습니다. 그래서 **중첩된 자원 해제**에 goto를 쓰는 관용적 패턴이 있습니다.

```c
// C에서 흔한 에러 처리 패턴
int func()
{
    A *a = alloc_a();
    if (!a) goto fail_a;

    B *b = alloc_b();
    if (!b) goto fail_b;

    // ... 작업 ...

    free_b(b);
fail_b:
    free_a(a);
fail_a:
    return -1;
}
```

리눅스 커널 소스에서 자주 보이는 형태입니다. 하지만 **C++에는 RAII와 예외가 있으므로 이 패턴이 필요 없습니다.** 소멸자가 알아서 정리해줍니다.

### 다중 반복문 탈출 — goto를 쓰고 싶어지는 유일한 순간

```cpp
// break는 가장 안쪽 반복문 하나만 탈출함
for (int i = 0; i < N; ++i)
    for (int j = 0; j < M; ++j)
        if (found(i, j))
            goto done;      // 두 반복문을 한 번에 탈출
done:
cout << "찾음" << endl;
```

C++에는 자바의 `break label` 같은 문법이 없어서, 이 경우만은 goto가 대안보다 깔끔하다는 의견도 있습니다. 다만 **함수로 분리해서 `return`하는 방법**이 더 권장됩니다.

```cpp
// 더 나은 방법 — 함수로 분리하고 return
bool search(int N, int M)
{
    for (int i = 0; i < N; ++i)
        for (int j = 0; j < M; ++j)
            if (found(i, j))
                return true;
    return false;
}
```

## 핵심 정리

1. `goto`는 **반복문이 아니라 무조건 점프문**이다. 반복처럼 보이는 건 뒤로 점프한 결과일 뿐이다.
2. `for`와 `while`은 **기능적으로 동일**하고, 서로 변환 가능하다. 차이는 의도 표현이다.
3. **반복 횟수를 알면 `for`, 종료 시점을 모르면 `while`**, "최소 한 번 실행"이면 `do-while`.
4. `for`의 카운터 변수는 반복문 안으로 스코프가 한정된다. 이건 `while`에 없는 장점이다.
5. `goto`는 **같은 함수 안에서만** 점프 가능하고, **변수 초기화를 건너뛰는 점프는 컴파일 에러**다.
6. `goto`는 실무에서 사실상 쓰지 않는다. **문법이 존재한다는 것과 읽을 줄 아는 것**만으로 충분하다.
