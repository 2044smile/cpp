# 5.3 switch-case

> 특별한 경우에 if 보다 간결하고 깔끔하게 코드 작성 가능

---

## 설명

### "switch-case, 왜 필요한가?"

if-else if 체인을 많이 써봤을 겁니다. 그런데 조건이 하나의 정수값에 따라 분기되는 상황이라면, switch-case가 훨씬 **구조적으로 명확합니다.**

컴파일러 입장에서도 switch-case는 **점프 테이블(jump table)** 로 최적화될 수 있어, **조건이 많을수록 if-else보다 빠릅니다.** 단순히 if의 문법적 대안이 아니라 내부 동작이 다를 수 있다"는 것만 기억

---

### 기본 구조 분석

```cpp
int x;
cin >> x;

switch (x)
{
    case 0:
        cout << "Zero";
        break;
    case 1:
        cout << "One";
        break;
    case 2:
        cout << "Two";
        break;
    default:
        cout << "Undefined input " << x;
}
```

switch 괄호 안에는 **정수형으로 평가되는 식**만 올 수 있습니다. `int`, `char`, `enum`, 그리고 이들의 `static_cast` 결과가 해당됩니다. `float`, `double`, `string`은 올 수 없습니다. 왜 그럴까요? 부동소수점은 정확한 동등 비교가 불가능하고, 점프 테이블은 연속된 정수 인덱스를 전제로 하기 때문입니다.

`default`는 어떤 case에도 해당하지 않을 때 실행됩니다. 마치 if-else의 마지막 `else`와 같습니다. **반드시 써야 하는 건 아니지만, 쓰는 습관을 들이세요.** 예상치 못한 입력에 대한 방어입니다.

---

### Fall-through — 가장 많이 실수하는 부분

```cpp
// break가 없다면 x=0 입력 시 "ZeroOneTwo" 출력
switch (x)
{
    case 0:
        cout << "Zero";
        // break 없음!
    case 1:
        cout << "One";
        // break 없음!
    case 2:
        cout << "Two";
        break;
}
```

`break`가 없으면 해당 case를 실행한 뒤 **다음 case로 그냥 떨어집니다(fall-through)**. 이걸 의도적으로 쓸 때도 있지만, 대부분은 **버그의 원인**입니다. 코드 리뷰에서 가장 자주 지적받는 실수이기도 합니다.

```cpp
// fall-through를 의도적으로 활용하는 예 (여러 case를 같은 처리로 묶기)
switch (x)
{
    case 1:
    case 2:
    case 3:
        cout << "1, 2, 3 중 하나입니다." << endl;
        break;
    default:
        cout << "그 외" << endl;
}
```

이처럼 `case 1:`, `case 2:`, `case 3:`을 연달아 쓰면 세 값 모두 같은 코드를 실행합니다. 이건 의도적인 fall-through입니다.

### enum class와 switch — static_cast 왜 필요한가?

```cpp
enum class Colors { BLACK, WHITE, RED, GREEN, BLUE };

void printColorName(Colors color)
{
    switch (static_cast<int>(color))
    {
        case 0: cout << "BLACK" << endl; break;
        case 1: cout << "WHITE" << endl; break;
        case 2: cout << "RED"   << endl; break;
        case 3: cout << "GREEN" << endl; break;
        case 4: cout << "BLUE"  << endl; break;
    }
}
```

`enum class`는 일반 `enum`과 달리 **정수로 암묵적 변환이 되지 않습니다.** 이것이 바로 `enum class`의 강점입니다. 실수로 다른 타입과 혼용하는 걸 컴파일러가 막아줍니다.

그런데 switch는 정수가 필요하므로, `static_cast<int>(color)`로 명시적으로 변환해야 합니다. 불편해 보이지만, 이 불편함이 **의도를 명확히 드러냅니다.**

더 좋은 방법은 `Colors::BLACK`을 직접 case에 쓰는 것입니다:

```cpp
switch (color)
{
    case Colors::BLACK: cout << "BLACK" << endl; break;
    case Colors::WHITE: cout << "WHITE" << endl; break;
    // ...
}
```

이게 가장 명확합니다. 코드에서 static_cast를 쓴 이유는 학습 과정에서 번호로 비교하는 방식도 직접 써보려 한 것입니다.

### switch 내부에서 변수 선언 — 이걸 꼭 알아야 합니다

이 부분은 많은 학생들이 헷갈립니다. `debug_test.cpp` 코드를 보겠습니다:

```cpp
switch(y)
{
    int n;      // (A) 선언은 되지만 초기화 코드는 실행되지 않음

case 0:
    int m;
    m = 5;
    break;

case 1:
    cout << &m << ", 값: " << m << endl;  // m을 초기화하지 않고 읽음
}
```

여기서 핵심 질문: **`int n;`과 `int m;`은 어떻게 됩니까?**

답: `n`과 `m`의 **메모리는 switch 블록 진입 시 스택에 할당**됩니다. 하지만 `case 1`로 점프하면 `m = 5;` 대입문은 건너뛰어집니다. 즉, `m`은 **메모리는 있지만 초기화되지 않은 상태**로 읽히는 겁니다. 이는 **미정의 동작(Undefined Behavior)** 입니다.

이 문제를 해결하는 방법이 `5.3 switch-case.cpp`의 마지막 예제입니다:

```cpp
switch(y)
{
    case 0:
    {           // 중괄호로 범위를 한정
        int z = 5;
        z = z + y;
        cout << z << endl;
        break;
    }
    case 1:
    {           // case마다 별도의 블록
        int z = 5;
        z = z - y;
        cout << z << endl;
        break;
    }
}
```

`case` 블록을 `{}`로 감싸면 각 case가 **독립된 스코프**를 가집니다. 다른 case의 변수에 접근할 수 없고, 초기화 점프 문제도 사라집니다. **case 안에서 변수를 선언할 때는 항상 중괄호로 감싸세요.**

## 추가 학습 내용

### switch vs if-else: 언제 무엇을 쓰나?

| 상황 | 권장 |
|------|------|
| 하나의 변수를 여러 **상수값**과 비교 | `switch` |
| 조건이 범위(`x > 10`), 여러 변수, bool 표현식 | `if-else` |
| 2~3개의 단순 분기 | 둘 다 무방 |
| `string`, `float` 비교 | `if-else` (switch 불가) |

### default를 맨 아래에 쓰지 않아도 됩니다

문법상 `default`는 어디에나 올 수 있습니다. 하지만 **관례적으로 맨 아래**에 씁니다. 읽는 사람이 "마지막 fallback"임을 직관적으로 알기 때문입니다.

### 점프 테이블과 성능

컴파일러는 case 값이 연속적이고 범위가 좁을 때 **점프 테이블**을 생성합니다. **이는 O(1) 분기입니다. if-else 체인은 O(n)입니다.** case가 10개 이상이고 값이 연속적이라면 switch가 성능상 유리합니다. 물론 현대 컴파일러는 if-else도 최적화하지만, 의도를 코드에 명시하는 것 자체가 좋은 습관입니다.

```
case 0, 1, 2, 3, 4  →  jump_table[x]()  // O(1)
if x==0 ... else if x==1 ...            // 순차 비교, O(n)
```

---

## 핵심 정리

1. `switch`는 **하나의 정수 표현식을 여러 상수값과 비교**할 때 사용한다.
2. `break`를 빠뜨리면 **fall-through**가 발생한다. 의도하지 않은 경우 버그다.
3. `case` 안에서 변수를 선언할 때는 **반드시 `{}`로 감싼다.**
4. `enum class`는 암묵적 정수 변환이 없으므로 `Colors::BLACK` 형태로 직접 case에 쓰거나 `static_cast`한다.
5. `default`는 생략 가능하지만, **방어적 프로그래밍**을 위해 항상 추가하는 습관을 들인다.
