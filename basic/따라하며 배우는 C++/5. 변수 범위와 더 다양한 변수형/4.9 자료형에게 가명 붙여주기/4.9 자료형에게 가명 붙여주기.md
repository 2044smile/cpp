# 4.9 자료형에게 가명 붙여주기

---

## 들어가며

코드를 작성하다 보면 `unsigned long long int` 처럼 **길고 복잡한 자료형 이름**을 반복해서 써야 할 때가 있습니다.  
C++에서는 자료형에 **별명(가명)** 을 붙여서 코드를 더 읽기 쉽고 유지보수하기 편하게 만들 수 있습니다.

방법은 두 가지입니다.

- `typedef` : C에서부터 이어진 전통적인 방법
- `using` : C++11에서 도입된 현대적인 방법 (권장)

---

## 1. 헤더 파일

```cpp
#include <iostream>
#include <cstdint>
```

| 헤더 | 역할 |
|---|---|
| `<iostream>` | `cin`, `cout` 입출력 |
| `<cstdint>` | 크기가 보장된 정수 자료형 제공 (`int8_t`, `int32_t` 등) |

---

## 2. `typedef` — 자료형에 가명 붙이기

```cpp
typedef double distance_t;  // double 에 distance_t 라는 가명을 붙임
```

문법 구조:

```
typedef  [기존 자료형]  [가명];
typedef    double      distance_t;
```

이제 `distance_t`는 `double`과 완전히 동일하게 사용할 수 있습니다.

```cpp
distance_t home_to_school = 3.5;   // double home_to_school = 3.5; 와 동일
distance_t earth_to_moon  = 384400.0;
```

### 가명을 쓰는 이유

| 상황 | 예시 |
|---|---|
| 의미를 명확하게 | `distance_t` → 이 값이 "거리"임을 한눈에 파악 |
| 긴 타입 단축 | `typedef unsigned long long int ull_t;` |
| 플랫폼 이식성 | 나중에 `double` → `float`으로 바꿀 때 `typedef` 한 줄만 수정 |

> **핵심** : `typedef`는 새로운 자료형을 **만드는** 게 아니라, 기존 자료형에 **다른 이름표를 붙이는** 것입니다. 실제 타입은 여전히 `double`입니다.

---

## 3. `_t` 접미사 관례

```cpp
typedef double distance_t;  // _t = type
std::int8_t i(97);          // _t 가명 (표준 라이브러리도 같은 관례 사용)
```

`_t`는 **"이것은 자료형(type)의 가명이다"** 라는 것을 코드 읽는 사람에게 알려주는 **네이밍 관례(convention)** 입니다.  
C++ 표준 라이브러리도 이 관례를 따릅니다.

| 이름 | 실제 타입 | 의미 |
|---|---|---|
| `std::int8_t` | `signed char` (8비트) | 정확히 8비트 크기의 정수 |
| `std::int16_t` | `short` (16비트) | 정확히 16비트 크기의 정수 |
| `std::int32_t` | `int` (32비트) | 정확히 32비트 크기의 정수 |
| `std::int64_t` | `long long` (64비트) | 정확히 64비트 크기의 정수 |

---

## 4. `<cstdint>` 와 크기 보장 정수형

```cpp
std::int8_t i(97);  // 97을 8비트 정수로 저장
```

`int`의 크기는 플랫폼마다 다를 수 있습니다(16비트 시스템에서는 2바이트, 32비트에서는 4바이트).  
`<cstdint>`의 자료형은 **어느 플랫폼에서도 크기가 보장**됩니다.

```cpp
std::int8_t i(97);
// int8_t는 8비트 = 1바이트
// 97 → ASCII 코드로 'a'
// cout << i 하면 'a' 출력 (주의: 숫자가 아닌 문자로 출력됨)
```

> `int8_t`는 내부적으로 `char`로 구현되는 경우가 많아 출력 시 문자로 보일 수 있습니다.  
> 숫자로 출력하려면 `(int)i` 처럼 캐스팅하세요.

---

## 5. `using` — C++11 권장 방식

`typedef`와 동일한 기능이지만 문법이 더 직관적입니다.

```cpp
// typedef 방식
typedef double distance_t;

// using 방식 (권장)
using distance_t = double;
```

`using`이 권장되는 이유는 **템플릿(template)과 함께 사용할 수 있기** 때문입니다.

```cpp
// typedef로는 불가능
// typedef std::vector<T> Vec<T>;  // 오류!

// using으로는 가능
template<typename T>
using Vec = std::vector<T>;  // OK

Vec<int>    nums;
Vec<string> names;
```

---

## 핵심 정리

| 개념 | 내용 |
|---|---|
| `typedef 타입 가명;` | 자료형에 별명을 붙임 (C 호환) |
| `using 가명 = 타입;` | 동일 기능, C++11 이후 권장 |
| `_t` 접미사 | 자료형 가명임을 나타내는 네이밍 관례 |
| `<cstdint>` | 크기가 보장된 정수형 (`int8_t`, `int32_t` 등) 제공 |
| 가명의 핵심 | 새 타입 생성 X, 기존 타입에 이름표를 추가하는 것 |

---

## 마치며

자료형 가명은 단순히 타이핑을 줄이는 것을 넘어, **코드의 의도를 표현**하고 **유지보수성을 높이는** 중요한 도구입니다.  
예를 들어 `distance_t`를 쓰면 나중에 `double` → `float`으로 바꾸더라도 `typedef` 한 줄만 수정하면 프로그램 전체가 반영됩니다.  
실무에서도 자주 쓰이는 패턴이니 익혀두세요.
